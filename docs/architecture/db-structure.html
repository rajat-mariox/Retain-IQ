RetainIQ · Data Architecture

Database structure

A database-per-service design: five isolated PostgreSQL databases, one per bounded context. There are no foreign keys across databases — a service owns its data outright, and cross-service references (an orgId, an employeeId) are plain UUIDs kept in step through domain events, not joins.

How isolated databases stay in sync

Transactional outbox

A service writes its own data and an OutboxEvent in one transaction, so a domain event can never be lost or double-sent relative to the write that caused it.

Broker

A relay publishes those events to the broker (Kafka or Redis Streams). Example: organization.created from identity → billing provisions a Subscription; organization.deleted → billing cancels it.

Idempotent inbox

Each consumer records every handled event in a ConsumedEvent row (unique on eventId + consumer), so at-least-once delivery becomes exactly-once processing — a redelivered event is a no-op.
